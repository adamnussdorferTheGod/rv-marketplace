**Part A: Extend VideoWalkthroughContext.tsx**

Add 4 new useCallback-wrapped action callbacks to the existing context, following the same pattern as play/pause/seekToSegment:

1. `loaded: () => void` — dispatches `{ type: 'LOADED' }`. Transitions loading -> playing.
2. `tick: (elapsedMs: number) => void` — dispatches `{ type: 'TICK', elapsedMs }`. Updates elapsed time in reducer.
3. `advanceSegment: (segmentIndex: number, actIndex: number) => void` — dispatches `{ type: 'SEGMENT_ADVANCE', segmentIndex, actIndex }`. Advances to next segment.
4. `end: () => void` — dispatches `{ type: 'END' }`. Transitions to ended state.

Update `VideoWalkthroughContextValue` interface to include these 4 new properties. Add them to the `useMemo` value object and dependency array. Do NOT expose raw dispatch — use named callbacks per project convention (DealKit/Narration contexts pattern).

**Part B: Create useTimeline hook**

Create `components/sections/VideoWalkthrough/hooks/useTimeline.ts` with a `useTimeline` export:

```typescript
interface UseTimelineOptions {
  isPlaying: boolean;
  segments: { durationMs: number }[];
  currentSegmentIndex: number;
  onTick: (elapsedMs: number) => void;
  onSegmentAdvance: (segmentIndex: number, actIndex: number) => void;
  onEnd: () => void;
  getActIndex: (segmentIndex: number) => number;
}
```

Implementation details:
- Use `requestAnimationFrame` (NOT setInterval) for the timing loop.
- Store `rafIdRef`, `previousTimeRef`, and `segmentElapsedRef` in `useRef` (NOT useState — avoid 60 re-renders/sec).
- `previousTimeRef` is set to `null` on play start; first frame computes zero delta.
- Cap delta time: if `delta > 100ms`, treat as 0 (handles tab switch drift — Pitfall 4 in research).
- Throttle `onTick` dispatches: only call `onTick` if at least 100ms have passed since last tick dispatch (use a `lastTickRef` counter). This prevents flooding the reducer at 60fps (Pitfall 5).
- When `segmentElapsedRef.current >= currentDuration`, check if `nextIndex >= segments.length`. If yes, call `onEnd()` and stop loop. Otherwise, reset `segmentElapsedRef` to 0 and call `onSegmentAdvance(nextIndex, getActIndex(nextIndex))`.
- Start the rAF loop in a `useEffect` that watches `isPlaying` and `tick` callback. Start when `isPlaying` is true, cancel on cleanup.
- Reset `segmentElapsedRef` to 0 in a separate `useEffect` watching `currentSegmentIndex`.

**Part A: Create KenBurnsLayer.module.css**

Define four `@keyframes` animations for Ken Burns motion. All use `scale3d` and `translate3d` for GPU-accelerated transforms (compositor thread, not main thread):

```css
@keyframes zoomIn {
  from { transform: scale3d(1, 1, 1) translate3d(0, 0, 0); }
  to { transform: scale3d(1.15, 1.15, 1) translate3d(0, 0, 0); }
}

@keyframes zoomOut {
  from { transform: scale3d(1.15, 1.15, 1) translate3d(0, 0, 0); }
  to { transform: scale3d(1, 1, 1) translate3d(0, 0, 0); }
}

@keyframes panLeft {
  from { transform: scale3d(1.1, 1.1, 1) translate3d(3%, 0, 0); }
  to { transform: scale3d(1.1, 1.1, 1) translate3d(-3%, 0, 0); }
}

@keyframes panRight {
  from { transform: scale3d(1.1, 1.1, 1) translate3d(-3%, 0, 0); }
  to { transform: scale3d(1.1, 1.1, 1) translate3d(3%, 0, 0); }
}
```

Add container `.layer` class: `position: absolute; inset: 0; overflow: hidden;`

Add `.photo` class: `width: 100%; height: 100%; object-fit: cover; animation-timing-function: linear; animation-fill-mode: forwards;`

Rationale for linear timing: easing creates acceleration that feels wrong for a documentary pan. Fill-mode forwards holds the final frame so the image does not snap back.

Add motion classes mapped to MotionPreset values:
- `.motionZoomIn { animation-name: zoomIn; }`
- `.motionZoomOut { animation-name: zoomOut; }`
- `.motionPanLeft { animation-name: panLeft; }`
- `.motionPanRight { animation-name: panRight; }`

Subtle scale values (1.0 -> 1.15 for zoom, 1.1 base for pan with 3% translate) — excessive zoom looks jarring on photo content. Pan pre-scales to 1.1x so edges are never visible.

```typescript
interface KenBurnsLayerProps {
  segment: VideoSegment;
  isActive: boolean;
  opacity: number;        // 0 or 1, driven by crossfade from parent

}
```

Create a `motionClassMap: Record<MotionPreset, string>` mapping each preset to its CSS Module class.

Render structure:
```tsx
<div className={styles.layer} style={{ opacity, transition: 'opacity 500ms ease-in-out' }}>
  <img
    src={segment.photoUrl}
    alt={segment.photoAlt}
    className={`${styles.photo} ${motionClassMap[segment.motionPreset]}`}
    style={{
      animationDuration: `${segment.durationMs}ms`,
      animationPlayState: isPaused ? 'paused' : 'running',
      willChange: isActive ? 'transform' : 'auto',
    }}
  />
</div>
```

Key implementation notes:
- `will-change: transform` ONLY on active layer via inline style (COMP-03). Do NOT put will-change in the CSS file — this would permanently allocate GPU textures.
- `animationPlayState` is set via inline style to freeze the Ken Burns motion when paused.
- `opacity` and `transition` on the outer div enable crossfade control from CompositionCanvas parent.
- `animationDuration` is set dynamically from segment data.
- Import `VideoSegment` and `MotionPreset` from `../../../../app/src/data/videoWalkthroughTypes`.
- Export as default function component.
